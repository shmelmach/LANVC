# LANVC — Политика безопасности и модель защиты (SECURITY.md)

## 1. Архитектура безопасности

LANVC разработан с соблюдением принципов Secure-by-Design для безопасного объединения домашних и игровых компьютеров через публичную сеть Интернет.

---

## 2. Криптографические протоколы и алгоритмы

1. **Транспортное шифрование:**
   - **TLS 1.3** для обоих видов транспорта:
     - Основной транспорт (QUIC): TLS 1.3 встроен в протокол QUIC (RFC 9001). Шифросюиты: `TLS_AES_128_GCM_SHA256` и `TLS_CHACHA20_POLY1305_SHA256`.
     - Резервный транспорт (WebSocket): TLS 1.3 поверх стандартного TCP-сокета на порту 443.
   - Запрещены устаревшие протоколы SSL 3.0, TLS 1.0, TLS 1.1, TLS 1.2.
   - Запрещены небезопасные шифры с CBC-режимом и слабыми ключами.

2. **Аутентификация сервера и защита от MITM (Man-in-the-Middle):**
   - При использовании самоподписанного сертификата сервер генерирует криптографический отпечаток **SHA-256** (например, `SHA256:7B:A2:3F:...`).
   - Клиент сохраняет отпечаток при первом доверенном подключении (TOFU — Trust-On-First-Use) либо администратор передаёт отпечаток участникам сети.
   - Любая попытка подмены сертификата на узлах провайдера или маршрутизаторах приводит к немедленному разрыву соединения с отображением ошибки `CERTIFICATE_FINGERPRINT_MISMATCH`.
   - Проверка сертификатов **никогда не отключается** слепо в коде (никаких `RemoteCertificateValidationCallback = (sender, cert, chain, errors) => true`).

3. **Хранение паролей на сервере (Argon2id):**
   - Пароль виртуальной сети **никогда** не хранится на сервере в открытом виде.
   - Используется алгоритм хеширования **Argon2id**, устойчивый к атакам с использованием GPU и ASIC:
     - Memory Size: **64 МБ (65536 КБ)**
     - Iterations: **3**
     - Parallelism: **4**
     - Salt: **16 байт криптографически стойкой случайной последовательности (`RandomNumberGenerator`)**
   - Проверка пароля выполняется с постоянным временем (`FixedTimeEquals`), исключая атаки по времени (Timing Attacks).

4. **Хранение паролей на клиенте (Windows Credential Manager):**
   - Пароли профилей подключения **не сохраняются** в открытых текстовых файлах или JSON.
   - Используется нативное хранилище учетных данных Windows: **Windows Credential Manager** (`Advapi32.dll` -> `CredWriteW` / `CredReadW` / `CredDeleteW`).
   - Пароли шифруются на уровне операционной системы механизмом DPAPI пользователя.

## 3. Защита от перебора паролей (Anti-Bruteforce & Rate Limiting)

На сервере реализован алгоритм **Token Bucket** для каждого подключающегося внешнего IPv4-адреса:
- Лимит попыток: не более 5 неверных попыток авторизации в течение 1 минуты.
- При превышении лимита IP-адрес временно блокируется:
  - 1-е нарушение: бан на 5 минут.
  - 2-е нарушение: бан на 30 минут.
  - Последующие: бан на 24 часа.
- Клиенту возвращается статус `4 = Banned / Rate Limited`.

## 4. Защита от переполнения буферов и атак на отказ в обслуживании (DoS)

1. **Проверка входящих пакетов (Sanity Checks):**
   - Максимальный размер пакета ограничен `MTU = 1500 байт`. Пакеты размером более 1500 байт немедленно сбрасываются.
   - Проверяется заголовок IPv4:
     - Версия протокола должна быть строго `4`.
     - Длина заголовка (`IHL`) должна быть не менее 20 байт.
     - Длина пакета из заголовка (`TotalLength`) должна строго соответствовать фактически принятому размеру.
     - `Source IP` должен строго совпадать с виртуальным IP, назначенным данному клиенту. Если клиент пытается отправить пакет с чужим `Source IP` (IP Spoofing внутри сети), пакет немедленно уничтожается.
2. **Лимит подключений:**
   - Сервер жестко ограничивает максимальное число одновременных участников до **10 пользователей** (конфигурируемо).
   - 11-му пользователю возвращается код ошибки `2 = Server Full`.
3. **Ограничение широковещательного флуда (Broadcast Storm Prevention):**
   - Сервер ограничивает частоту широковещательных пакетов (`255.255.255.255` и `10.77.0.255`) до 100 пакетов в секунду на одного клиента.

## 5. Политика ведения журналов (Privacy & Secrets)

- В логах клиента и сервера **категорически запрещено** отображение:
  - Паролей в открытом виде.
  - Хешей паролей.
  - Приватных ключей TLS.
  - Содержимого пользовательских пакетов (payloads игр).
- Журналируются исключительно:
  - Метки времени.
  - Сетевые события (подключение, отключение, смена транспорта).
  - Назначенные виртуальные IP.
  - Агрегированные счётчики трафика и кодовые ошибки.
